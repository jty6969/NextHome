# NextHome · 房智罗盘

根目录为新版 NextHome：原生前端、Worker API、Drizzle 数据结构及 SQLite/D1 存储。包含房源录入与编辑、筛选、地图与详情、中英文切换、买卖双方工作台、AI 咨询、消息、议价、预约和双方确认的交易流程。

新版源码来自本地已发布版本 `4d7ab8948b5dbf666dca286a9e076118729c6140`。GitHub 原有 `2cff721` 版本的应用源码和房源资源完整保留在 `legacy/victor/`；本次提交基于原有远程历史，未覆盖或改写历史提交。

## 本地运行新版

安装 Node.js **22.13 或更高版本**，在仓库根目录执行：

```powershell
npm ci
npm run dev
```

打开 <http://127.0.0.1:3000>。首次运行会在 `.local/nexthome.sqlite` 创建数据库并应用 `drizzle/` 迁移，再从应用自带的房源快照导入数据。该数据库不提交到 Git。

买家和卖家可通过页面注册。示例管理员为 `管理员账号1`，示例密码为 `123456`，仅用于本地演示；部署到自己的生产环境前应配置并管理自己的账号。

AI 功能需要服务端环境变量；未配置时页面仍可运行，AI 请求会提示配置缺失：

```powershell
$env:DEEPSEEK_API_KEY = '填入自己的服务端密钥'
npm run dev
```

不要将真实密钥写入源码、提交记录或前端。AI 成功回答还需要上游账号有可用余额。地图的服务端配置和房源同步说明分别见 [MAP_SETUP.md](MAP_SETUP.md) 与 [LISTING_SYNC.md](LISTING_SYNC.md)。本地开发服务器仅监听 `127.0.0.1`。

本地也可将完整密钥单独保存为 `.local/deepseek-api-key.txt`，开发服务器启动时会自动读取；`DEEPSEEK_API_KEY` 环境变量优先。默认模型为 `deepseek-flash`，可通过服务端 `DEEPSEEK_MODEL` 调整。线上密钥仍由 Sites 服务端秘密变量保存，本地密钥文件不会上传。指定本地端口可设置 `$env:PORT = '3108'`；重启已有隔离预览时，可用 `NEXTHOME_DB_PATH` 指向原数据库文件以保留记录。

## 验证与构建

首页采用 AI 对话布局。左侧导航可展开，提供新对话、历史记录、手动查找房源、地图找房、预约看房及设置。右上角按管理员房源录入、语言、账号的顺序排列；录入入口由既有管理员角色和服务端权限共同控制。语言和侧边栏偏好保存在浏览器，新对话清空当前展示和输入，保留服务端历史及购房需求画像。

房源列表使用 `?view=list`，地图使用 `?view=map`，原有详情链接继续有效。中央加号菜单和设置中保留购房需求、挂牌及交易工作台入口，首页没有预算、通勤、购房流程三个快捷选项。历史和预约复用现有 `/api/advisor/` 接口，录入复用 `/api/admin/listings`。

`tests/home.test.mjs` 覆盖首页语言持久化与草稿、访客/买家/卖家/管理员入口、账号退出、原有导航、预约入口、AI 发送与失败恢复、历史记录、键盘及语音事件。外部 AI、地图服务和实际麦克风需要在有配置及权限的环境中单独验收。

首页默认打开买房助手，上方“卖房 / 买房”分段控件支持方向键、Home/End 和减少动态效果。卖房模式复用服务端 DeepSeek 配置，用户明确出售、挂牌或卖旧买新后开启对话式挂牌；知识咨询不强制采集。先收集房屋基本信息，再询问出售原因和万元人民币售价；提前给出的信息直接记录，阶段清单仅首次展示，后续每轮优先追问 1–2 项。不确定或暂不提供的项保留未完成状态并暂停催问，支持自然语言修改、清空和冲突确认。旧卖房信息及置换需求继续私密保留；原卡片和编辑入口已移除。

信息齐全由服务端结构化校验判断，楼层与总楼层分开校验，电梯为“无”也是有效信息。首次完整时自动显示“挂牌信息”窗口，可分组修改、返回对话或确认保存；关闭不会创建房源。首次展示状态持久化，之后可用“查看挂牌信息”重新打开。后台卖房回复晚到时不会打断买房，返回卖房后再核对。窗口支持焦点限制、Escape 关闭、手机单列布局和保存失败重试。

`drizzle/0006_dry_leper_queen.sql` 保存卖房信息和独立对话；`drizzle/0007_lame_mister_sinister.sql` 增量增加采集流程状态和 `seller_listing_drafts` 私密房源草稿。两者均按账号、房屋标识隔离，可通过“新增房屋”及下拉菜单管理多套房；输入框草稿也按房屋隔离。刷新、重新登录可恢复。旧的明确数字楼层描述可转换为独立字段并保留原文。版本检查防止后台回复覆盖手动编辑，确认保存使用唯一约束和条件 UPSERT 避免网络重试或重复点击生成多条草稿。

确认保存仅写入当前用户的私密房源草稿，不写公开房源库、同步导出或卖家权限表。保存后可“前往公开挂牌”，复用原有提交表单和登录权限；该入口仅带入城市、区域、小区，详细门牌不自动带入，公开提交仍需用户主动确认。原有公开房源流程的行为与权限保持一致。发布构建携带全部增量数据库迁移。

`tests/selling.test.mjs` 和 `tests/home.test.mjs` 覆盖分阶段采集、提前补充、自然语言修改、冲突与清空、暂不提供、完整性判断、自动弹窗及关闭、后台晚到回复、恢复、账号和多房屋隔离、保存失败重试及幂等私密保存。

```powershell
npm test
npm run build
npm run sync:listings -- --help
```

构建输出为 `dist/client/`、`dist/server/index.js` 和 `dist/.openai/drizzle/`。`dist/` 为生成目录，不入库。Worker 使用 `DB` 数据库绑定和 `ASSETS` 静态资源绑定；站点构建描述位于 `.openai/hosting.json`。GitHub 上传不等于部署网站，也不会迁移线上用户数据库。

## 目录

| 路径 | 用途 |
| --- | --- |
| `index.html`、`assets/` | 新版页面、样式、工作台脚本、图片与房源导入快照 |
| `worker/` | 鉴权、房源、地图代理、AI 和买卖业务 API |
| `db/`、`drizzle/` | 数据结构与增量数据库迁移 |
| `scripts/` | 构建、本地服务器、同步及可选旧数据迁移 |
| `tests/` | 隔离数据库和页面回归测试 |
| `legacy/victor/` | 同伴原有版本，保留原代码及资源 |

房源资源包括历史挂牌与演示数据，不代表实时成交价；运行时业务记录以数据库为准。

## 运行保留的旧版

```powershell
cd legacy/victor
node server.js
```

也可在该目录双击 `start.bat`。请先停止新版，避免两版同时占用 3000 端口。旧版使用独立的 CommonJS 包设置，保留原有语音输入、双语界面及 AI 咨询逻辑；详细说明见 [旧版 README](legacy/victor/README.md)。如需旧版 AI，将其 `ai-config.example.json` 复制为同目录 `ai-config.json`，自行填写密钥。

`scripts/import-victor.mjs` 与 `scripts/migrate-victor.mjs` 是可选的本地旧数据导入工具，默认读取未提交的 `NextHome-Victor/`。普通运行新版无需这些私有数据；迁移前自行备份数据库，并准备拥有访问权限的本地数据。旧会话和旧客户端交易快照不会转换为有效交易确认。

## 不入库的内容

真实密钥与 `.env` 文件、用户数据与会话、本地数据库、`listing-data/` 导出、日志、构建产物、`outputs/`、内部 Word 文档和内部合并报告均不提交。已有内部 Word 文档保留在本地及原 Git 历史中，从本次 `main` 文件树移除。

AI 发送故障排查：买卖两侧复用 `worker/deepseek.js`。服务端在写入对话前对临时网络/5xx/限流、空内容与异常 JSON 最多重试一次，并限制单次请求时长、输出长度，交互式对话显式关闭思考模式。永久凭据或配置错误不重试。前端立即显示发送中消息，失败保留原文、展示明确错误并可原位重试；辅助资料刷新不再阻塞已经收到的回复，请求与响应正文均受超时限制。`advisor_ai_failure` 日志包含请求标识、买卖模式、上游状态、失败阶段和重试次数，不包含用户描述、房屋地址或凭据。相关测试见 `tests/deepseek.test.mjs` 及首页发送回归。
